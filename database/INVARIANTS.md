# Let's Chow — Financial Invariants & Application-Level Rules

This document describes the business rules and data invariants that **cannot be fully enforced by MySQL constraints** and must be implemented in the PHP application layer using transactions.

---

## 1. Order Totals Consistency

### Invariant
```
orders.total_ngn = orders.subtotal_ngn + orders.delivery_fee_ngn
orders.subtotal_ngn = SUM(order_items.line_total_ngn) FOR order_items WHERE order_id = orders.id
order_items.line_total_ngn = order_items.unit_price_ngn * order_items.quantity
```

### Enforcement
- **On order creation**: Compute `subtotal_ngn` from cart items, set `delivery_fee_ngn` (0 for pickup, quoted for delivery), compute `total_ngn`.
- **On order item changes** (add/remove/update quantity): Recalculate `subtotal_ngn` and `total_ngn` in the same transaction.
- **On delivery fee quote/accept/reject**: Update `delivery_fee_ngn`, recompute `total_ngn`.
- **Use a single transaction** for all related writes.

### SQL Helper (for verification)
```sql
SELECT o.id, o.total_ngn, o.subtotal_ngn, o.delivery_fee_ngn,
       COALESCE(SUM(oi.line_total_ngn), 0) AS computed_subtotal
FROM orders o
LEFT JOIN order_items oi ON oi.order_id = o.id
GROUP BY o.id
HAVING o.total_ngn <> (COALESCE(SUM(oi.line_total_ngn), 0) + o.delivery_fee_ngn)
   OR o.subtotal_ngn <> COALESCE(SUM(oi.line_total_ngn), 0);
```

## 2. Order Item Snapshots

### Invariant
When an order item is created:
- `item_name` = `menu_items.name` at that moment
- `unit_price_ngn` = `menu_items.price_ngn` at that moment
- `menu_item_id` = `menu_items.id` (nullable, SET NULL on menu item deletion)

### Enforcement
- Application must copy values from `menu_items` into `order_items` at insert time.
- Never compute `line_total_ngn` from live menu prices — always use the snapshot.

## 3. Payment Verification

### Invariant
- A payment with `status = 'paid'` must have `amount_ngn = orders.total_ngn` (for full payment) or `amount_ngn <= orders.total_ngn` (for partial, if supported).
- `orders.payment_status` must reflect the aggregate state of its payments:
  - Any `paid` payment → `payment_status = 'paid'`
  - All `failed` → `payment_status = 'failed'`
  - Any `refunded` → `payment_status = 'refunded'`
  - Else `pending`

### Enforcement
- On payment callback/webhook: verify signature, then update payment row and order's `payment_status` in **one transaction**.
- Use `idempotency_key` to prevent duplicate payment creation from retries.

## 4. Valid Order Status Transitions

### State Machine
```
awaiting_review
    ├── (staff quotes fee) → awaiting_customer [delivery_fee_status = 'quoted']
    ├── (staff confirms pickup) → confirmed
    └── (cancel) → cancelled

awaiting_customer
    ├── (customer accepts fee) → confirmed [delivery_fee_status = 'accepted', delivery_fee_accepted=1, delivery_fee_accepted_at=NOW()]
    ├── (customer rejects fee) → awaiting_review [delivery_fee_status = 'rejected']
    └── (timeout/cancel) → cancelled

confirmed
    ├── (kitchen starts) → preparing
    └── (cancel) → cancelled

preparing
    ├── (ready for pickup/delivery) → ready
    └── (cancel) → cancelled

ready
    ├── (driver dispatched) → out_for_delivery
    ├── (customer picks up) → completed
    └── (cancel) → cancelled

out_for_delivery
    ├── (delivered) → completed
    └── (issue) → awaiting_review / cancelled

completed → (terminal)
cancelled → (terminal)
```

### Enforcement
- **Application layer** must validate transitions before UPDATE.
- Store each transition in `order_status_history` with `actor_type`, `actor_id`, `change_note`.
- Consider a PHP transition validator function/class.

## 5. Delivery Fee Workflow

### Rules
| `delivery_fee_status` | `delivery_fee_ngn` | `delivery_fee_accepted` | `delivery_fee_accepted_at` | Meaning |
|----------------------|-------------------|------------------------|---------------------------|---------|
| `not_quoted` | 0.00 | 0 | NULL | Initial state (pickup or delivery not yet quoted) |
| `quoted` | > 0 | 0 | NULL | Staff quoted fee, awaiting customer |
| `accepted` | > 0 | 1 | timestamp | Customer accepted, order can proceed |
| `rejected` | > 0 | 0 | NULL | Customer rejected, back to `awaiting_review` |

### Enforcement
- On quote: set `delivery_fee_ngn`, `delivery_fee_status = 'quoted'`, `order_status = 'awaiting_customer'`.
- On accept: set `delivery_fee_status = 'accepted'`, `delivery_fee_accepted = 1`, `delivery_fee_accepted_at = NOW()`, `order_status = 'confirmed'`.
- On reject: set `delivery_fee_status = 'rejected'`, `order_status = 'awaiting_review'` (staff can re-quote).

## 6. Payment Idempotency

### Invariant
- Each payment attempt must use a unique `idempotency_key` (generated by PHP, e.g., `bin2hex(random_bytes(16))`).
- `idempotency_key` has a unique constraint — duplicate inserts will fail.
- On provider callback: look up by `provider_reference` AND verify `idempotency_key` matches expected.

### Enforcement
```php
// Creating a payment record
$idempotencyKey = bin2hex(random_bytes(16));
$stmt = $pdo->prepare("INSERT INTO payments (..., idempotency_key) VALUES (..., ?)");
$stmt->execute([..., $idempotencyKey]);
```

## 7. Actor Tracking in Status History

### Invariant
Every `order_status_history` row must have:
- `actor_type` ∈ {`admin`, `customer`, `system`}
- `actor_id`: reference appropriate to type (admin ID, customer phone hash, NULL for system)
- For admin actions: also populate `actor_admin_id` for backward compatibility

### Enforcement
- PHP service layer sets these fields when recording history.
- Never rely on triggers — explicit is clearer for audit.

---

## 8. Order Deletion Prohibition

### Rule
**Orders are never hard-deleted in normal operations.**
- `order_items` and `order_status_history` FKs are `ON DELETE RESTRICT`.
- Cancellation = `order_status = 'cancelled'`.
- If archival is needed: create a separate admin-only process that exports then deletes (with full audit log).

---

## 9. Menu Item Availability

### Rule
- `is_available = 1` → item can be added to cart/orders.
- `is_available = 0` → item **visible** in menu but **disabled** for ordering (greyed out, "Currently unavailable" badge).
- Application layer must check `is_available` before allowing `order_items` insert.

## 10. Public Reference Generation

### Format
- 12 characters, uppercase alphanumeric (A-Z, 0-9).
- Example: `LC7K9M2P4XQ9`

### Generation (PHP)
```php
function generatePublicRef(): string {
    $bytes = random_bytes(8); // 8 bytes = ~1.8e19 possibilities in base36
    return strtoupper(substr(base_convert(bin2hex($bytes), 16, 36), 0, 12));
}
// Or use a custom base36 alphabet for better distribution
```

### Collision Handling
- Unique constraint on `public_ref` — catch `PDOException` with code 23000 and retry.

---

## 11. Timezone Consistency

### Rule
- All `TIMESTAMP` columns store UTC.
- PDO connection sets `SET time_zone = '+00:00'` on connect.
- PHP must use UTC: `new DateTime('now', new DateTimeZone('UTC'))` or `gmdate()`.

## Transaction Boundaries (Summary)

| Operation | Tables Involved | Single Transaction? |
|-----------|-----------------|---------------------|
| Create order + items | orders, order_items | ✅ Yes |
| Add/remove/update order item | orders, order_items | ✅ Yes |
| Quote delivery fee | orders | ✅ Yes |
| Accept/reject delivery fee | orders | ✅ Yes |
| Record payment + update order | payments, orders | ✅ Yes |
| Status transition | orders, order_status_history | ✅ Yes |
| Cancel order | orders, order_status_history | ✅ Yes |

## Verification Queries (Run Periodically)

```sql
-- 1. Orders with inconsistent totals
SELECT o.id, o.public_ref, o.total_ngn, o.subtotal_ngn, o.delivery_fee_ngn,
       COALESCE(SUM(oi.line_total_ngn), 0) AS computed_subtotal
FROM orders o
LEFT JOIN order_items oi ON oi.order_id = o.id
GROUP BY o.id
HAVING o.total_ngn <> (COALESCE(SUM(oi.line_total_ngn), 0) + o.delivery_fee_ngn)
    OR o.subtotal_ngn <> COALESCE(SUM(oi.line_total_ngn), 0);

-- 2. Payments without idempotency_key
SELECT * FROM payments WHERE idempotency_key IS NULL;

-- 3. Status history without actor info
SELECT * FROM order_status_history WHERE actor_type = 'system' AND actor_id IS NULL AND actor_admin_id IS NULL;

-- 4. Delivery fee status inconsistencies
SELECT * FROM orders
WHERE (delivery_fee_status = 'accepted' AND (delivery_fee_accepted = 0 OR delivery_fee_accepted_at IS NULL))
   OR (delivery_fee_status = 'rejected' AND order_status <> 'awaiting_review')
   OR (delivery_fee_status = 'quoted' AND order_status <> 'awaiting_customer')
   OR (delivery_fee_status = 'not_quoted' AND delivery_fee_ngn > 0);
```
